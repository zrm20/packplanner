# Domain Docs

PackPlanner uses a single context: `GLOSSARY.md` at the repository root and
architecture decision records under `docs/adr/`.

## Before exploring

Read `GLOSSARY.md` and the ADRs relevant to the area being explored. If they
don't exist, proceed silently. The `domain-modeling` skill creates them when
terms or decisions are resolved.

## Vocabulary

Use the glossary's terms when naming domain concepts in issues, proposals,
hypotheses, tests, and code. If a term is missing, reconsider whether it belongs
to this domain; record genuine gaps through `domain-modeling`.

## Decisions

If a proposal conflicts with an existing ADR, identify the conflict and explain
why the decision should be reopened before changing it.
